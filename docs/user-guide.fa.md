# راهنمای پایهٔ آزمایشی

## ساخت مالک

۱. دستور نصب README را اجرا کنید.
۲. آدرس `/setup` نمایش‌داده‌شده را باز کنید.
۳. توکن پنج‌دقیقه‌ای، نام کاربری و رمز قوی را وارد کنید.
۴. پس از ساخت مالک از `/login` وارد شوید. برای توکن تازه، `sudo papilio setup-token`
را روی سرور اجرا کنید.

پس از راه‌اندازی، مسیر ساخت مالک بسته می‌شود. اعتبارسنجی رمز با Django است و حداقل
پیش‌فرض ۱۲ کاراکتر دارد. توکن راه‌اندازی با API key معمولی متفاوت است. API key و
2FA اختیاری هنوز در مراحل بعدی قرار دارند.

## بررسی کارهای پس‌زمینه

صفحهٔ اصلی، وضعیت دیتابیس، کش و آخرین گزارش هر دو worker را نشان می‌دهد. گزارش
تازه، تضمینِ رخ‌ندادن خرابی پس از آن لحظه نیست. بررسی ارتباطی یا پردازشی را بزنید
و با «تازه‌سازی» نتیجهٔ ثبت‌شده را ببینید. فقط کاری که هنوز در صف است از این مسیر
لغو می‌شود. هر ادمین فقط عملیات خودش را می‌خواند یا لغو می‌کند؛ دسترسی لغوشده
اجازهٔ اجرای بررسی تازه ندارد.

## تغییر زمان‌بندی

مالک می‌تواند فاصلهٔ اجرا و فعال‌بودن تحویل پیام و گزارش workerها را در صفحهٔ اصلی
تغییر دهد. تغییرات با scheduler دیتابیس و بدون restart اعمال می‌شوند. ذخیرهٔ نسخهٔ
قدیمی تنظیمات رد می‌شود؛ پیش از تلاش دوباره تازه‌سازی کنید. غیرفعال‌کردن تحویل،
کارها را در صف نگه می‌دارد؛ غیرفعال‌کردن گزارش worker پس از انقضای گزارش قبلی،
وضعیت آمادگی را ناموفق می‌کند.

## فرمان و محیط

لانچر نصب‌شده به محیط و شناسهٔ انتخاب‌شده هنگام نصب اشاره می‌کند. برای انتخاب
نصب دیگر، گزینه‌ها را پیش از نام فرمان بنویسید:

```sh
sudo papilio --environment dev --instance work status
sudo papilio logs worker-io --tail 50 --follow
sudo papilio doctor --timeout 120
```

داده و تنظیمات در `/opt/papilio/ENVIRONMENT/INSTANCE/` هستند. فایل `runtime.env`
خصوصی است. شناسه و مسیرهای تولیدشده باید با `installation.json` هماهنگ بمانند؛
تغییر مسیر به خارج نصب یا واردکردن متغیرهای اجرای میزبان پذیرفته نمی‌شود. تنظیمات
راه‌اندازی معمولاً به restart سرویس مرتبط نیاز دارند.

## پشتیبان‌گیری و بازیابی

```sh
sudo papilio backup --output /private/path/papilio.tar.gz
sudo papilio restore /private/path/papilio.tar.gz
```

آرشیو فشرده شامل دیتابیس، تنظیمات و دادهٔ گواهی Caddy است. این انتشار پایه هنوز
رمزگذاری اختیاری ندارد؛ بکاپ دارای اطلاعات محرمانه است و باید خصوصی نگه داشته
شود. رمزگذاری با رمز دلخواه، چندقسمتی‌کردن، ارسال زمان‌بندی‌شده به تلگرام/دیسکورد
و بازیابی از پنل، ردیف‌های جدا و تکمیل‌نشده‌اند.

بازیابی نسخه، محیط و شناسهٔ سازگار می‌خواهد؛ فایل و checksum را بررسی و ابتدا از
وضعیت فعلی بکاپ می‌گیرد. سپس سرویس‌های برنامه متوقف می‌شوند و بازیابی با نقش
دیتابیس بدون دسترسی superuser انجام می‌شود. کلید برنامه بازیابی می‌شود ولی
اعتبارنامه‌ها و مسیرهای زیرساخت مقصد حفظ می‌شوند. پیام‌های صف همین نصب پاک و
عملیات در انتظار از outbox دیتابیس پیگیری می‌شوند. اگر شکست خورد، بکاپ پیش از
بازیابی را حفظ و لاگ‌ها را بررسی کنید؛ شکست، موفقیت اعلام نمی‌شود.

## به‌روزرسانی

```sh
sudo papilio update
sudo papilio update --version VERSION
sudo papilio update --source /opt/papilio/releases/papilio-NEW_VERSION
```

فقط نسخهٔ منتشرشده قابل دریافت است. پیش از اجرای migration بکاپ گرفته می‌شود.
سازگاری ارتقای هر انتشار باید جداگانه آزموده شود. مهاجرت از پیاده‌سازی حذف‌شده
جزو این بازسازی نیست. `stop` داده‌ها را حذف نمی‌کند و `status` صرفاً وضعیت را می‌خواند.
