# عامل Go نود — مسیر MVP در حال ساخت

[English](README.md)

عامل اجرایی اکنون با mTLS به API محلی Xray متصل می‌شود. در آزمون، فرمان HTTPS
کاربر می‌سازد، کلاینت واقعی ترافیک عبور می‌دهد و حذف کاربر اتصال‌های جدید را رد
می‌کند. این کد در شاخهٔ main است و در بستهٔ پایهٔ `0.1.0-alpha.1` وجود ندارد.

ثبت نود و صدور گواهی از پنل، مدیریت فرایند هسته، نصب یک‌خطی نود و ساخت اشتراک
از Django هنوز تکمیل نشده‌اند. عامل فعلی به Xray از قبل اجراشده متصل می‌شود.

## اجرای توسعه با گواهی آماده

```sh
cd node/agent
go build -trimpath -o /tmp/papilio-agent ./cmd/papilio-agent
/tmp/papilio-agent -config /etc/papilio-agent/agent.json
```

[نمونهٔ تنظیمات](config.example.json) همهٔ پارامترهای فعلی را نشان می‌دهد. شناسه‌های
نمونه باید با شناسهٔ صادرشده برای نصب و نود جایگزین شوند. مسیر نسبی گواهی و کلید
از پوشهٔ فایل تنظیمات محاسبه می‌شود. خواندن فایل هیچ مقداری را بازنویسی نمی‌کند؛
فیلد اختیاریِ غایب مقدار پیش‌فرض می‌گیرد. مسیر نصب نهایی باید همهٔ مقدارهای انتخابی
را صریح ذخیره کند. تغییر تنظیمات فعلاً به راه‌اندازی مجدد عامل نیاز دارد؛ کنترل
این تنظیمات از پنل هنوز پیاده نشده است.

گواهی سرور با کاربرد ServerAuth باید دقیقاً این URI را داشته باشد:

```text
spiffe://papilio/DEPLOYMENT_UUID/nodes/NODE_UUID/agent
```

گواهی کلاینت کنترل با کاربرد ClientAuth باید دقیقاً این URI را داشته باشد:

```text
spiffe://papilio/DEPLOYMENT_UUID/nodes/NODE_UUID/control
```

شناسه‌ها باید با تنظیمات نود یکسان باشند. گواهی بدون محدوده، منقضی، نامعتبر یا
متعلق به نصب/نود دیگر رد می‌شود. اعتبار گواهی کلاینت در هر درخواست نیز بررسی
می‌شود تا اتصال باز پس از انقضا مجوز فرمان نداشته باشد. کلاینت باید اعتماد، نام
میزبان و هویت نودِ سرور را هم بررسی کند. صدور و چرخش خودکار گواهی در ادامه است.

## قرارداد کنترل نسخهٔ ۱

| روش | مسیر | کاربرد |
| --- | --- | --- |
| GET | `/v1/nodes/{node_id}/status` | شناسهٔ نود، نسخهٔ قرارداد و uptime واقعی هسته |
| PUT | `/v1/nodes/{node_id}/xray/users/{email}` | ایجاد یا اصلاح کاربر با `inbound_tag`، `uuid`، `flow` و `level` |
| DELETE | `/v1/nodes/{node_id}/xray/users/{email}?inbound_tag=TAG` | حذف تکرارپذیر از inbound مشخص |
| GET | `/v1/nodes/{node_id}/xray/traffic` | شمارنده‌های واقعی مصرف بدون صفرکردن آن‌ها |

شناسهٔ مسیر باید متعلق به همین نود باشد. ایمیل از مسیر گرفته می‌شود؛ بدنه نمی‌تواند
هویت نود یا مالکیت را تغییر دهد. سقف بدنه، سقف پاسخ gRPC، مهلت درخواست و خاموش‌شدن
در فایل تنظیمات صریح‌اند؛ سقف تعداد حساب به محصول اضافه نشده است. مهلت نوشتن HTTP
دو برابر مهلت درخواست است. TLS 1.3 و کنترل هویت گواهی با درخواست خاموش نمی‌شوند.

## مرز آزمون و کارهای باقی‌مانده

آزمون‌ها هسته و کلاینت واقعی، TLS واقعی، تغییر اعتبارنامه، تکرار و هم‌زمانی، لغو،
انقضای گواهی روی اتصال باز و timeout/بازیابی هسته را اجرا می‌کنند. باینری عامل هم
با race detector ساخته و اجرا می‌شود. همهٔ فرایندها و فایل‌های آزمون مستقل‌اند.

ترافیک آزمون از VLESS روی loopback عبور می‌کند؛ تنظیم انتقال رمز‌شدهٔ عمومی VPN
هنوز آزموده نشده است. حذف کاربر برای اتصال جدید تأیید شده؛ قطع اتصال باز هنوز
تأیید نشده است. تغییر اعتبارنامهٔ هسته تراکنش چندمرحله‌ای ندارد و با شکست افزودن،
ممکن است کاربر قبلی حذف شده باشد؛ هماهنگ‌کننده باید وضعیت مطلوب را نگه دارد و
دوباره اعمال کند. آمار با restart هسته صفر می‌شود؛ نگه‌داری epoch، سهمیه و حسابداری
مالی در این آداپتور انجام نمی‌شود. چرخهٔ کامل خرید و تحویل MVP همچنان باقی است.
