## چرا پاپیلیو؟

مدیریت مشتری، کانفیگ، پرداخت و بات فروش را در یک فضای کاری قابل تنظیم دنبال کنید.
منطق کسب‌وکار در API قرار دارد؛ رابط وب، بات تلگرام و عامل نود مسئولیت‌های مشخص دارند.

- **پلن متناسب با نیاز مشتری:** حجمی و مدت‌دار، حجمی بدون انقضا، یا نامحدود با انقضا؛ همراه یک یا چند کانفیگ.
- **پرداخت قابل پیگیری:** اطلاعات مقصد ثبت‌شده در فاکتور، مبلغ صریح ریالی، اعتبار کیف پول، خرید، بازپرداخت و تمدید.
- **اتوماسیون قابل کنترل:** زمان‌بندی، سیاست‌ها و ظرفیت‌های قابل تنظیم، همراه مسیر بررسی و بازیابی.
- **اختیار زیرساخت و داده:** تنظیمات JSON، سیاست تجاری و قراردادهای API در اختیار نصب‌کننده هستند.

## امکانات

| بخش | قابلیت‌های موجود |
| --- | --- |
| کانفیگ | تنظیم پروتکل، ویرایش تنظیمات و JSON سرور، باندل کانفیگ و خروجی هسته؛ پشتیبانی عملیاتی هر مورد به عامل و آزمون مربوط وابسته است. |
| مشتری و دسترسی | مشتری، کانفیگ‌های اختصاص‌یافته، نقش و دسترسی مدیر و قابلیت‌های نمایندگی. |
| فروش | خرید با کیف پول، شروط ثبت‌شدهٔ خرید، سیاست تمدید و مسیر بازیابی تحویل و بازپرداخت. |
| پرداخت | کارت/شبا/حساب، بررسی دستی، شناسهٔ چهاررقمی اختیاری ریالی و تطبیق پیامک گوشی ثبت‌شده. |
| تجربهٔ مشتری | گردش خرید تلگرام، QR، اطلاعات مصرف، تست، پشتیبانی، گروه تخفیف و اعلان. |
| عملیات | بررسی پرداخت، سلامت نود، بازیابی سفارش و توجه به وضعیت اشتراک با زمان‌بندی بومی. |

ثبت گوشی، منبع پیامک را احراز می‌کند؛ تطبیق مبهم به بررسی نیاز دارد. تصویر رسید به‌تنهایی اثبات واریز نیست.
جزئیات قراردادها در [مرجع امکانات انگلیسی](docs/feature-reference.en.md) آمده است.

## راه‌اندازی

[آموزش کار با پنل](docs/user-guide.fa.md) و [English user guide](docs/user-guide.en.md)
انتخاب ظاهر، ساخت پلن، پرداخت، تمدید و عیب‌یابی را توضیح می‌دهند.

[آموزش فارسی](docs/getting-started.fa.md) و [English guide](docs/getting-started.en.md) را ببینید.
نصب‌کننده API، پنل و سرویس‌های وظایف را اجرا می‌کند؛ تلگرام اختیاری است.
هسته‌های پروکسی به تنظیم و پذیرش جداگانه نیاز دارند.
برای واردکردن محرمانهٔ کلید API گوگل ویژن، گزینهٔ `--enable-ocr` را بدهید.
پس از نصب، از checkout دستور `scripts/deploy/doctor.sh` را اجرا کنید؛ بعد از نصب یک‌خطی مسیر آن
`$HOME/.local/share/papilio-proxy/source/scripts/deploy/doctor.sh` است.
این دستور فقط healthcheckهای Compose را بررسی می‌کند و اجرای worker/scheduler، OCR، پرداخت یا runtime نود را نمی‌آزماید.

## مسیر محصول

انتخاب **فارسی/انگلیسی**، جهت **RTL/LTR** و تم **روشن/تاریک/سیستم** اکنون موجود است.
ورود، نمای کلی، ناوبری و تعدادی از خطاهای مشترک ترجمه شده‌اند؛ ترجمهٔ سایر صفحات هنوز کامل نیست.
انتخاب در مرورگر ذخیره می‌شود و نبود دسترسی به ذخیره‌سازی پیام مشخص دارد.
قرارداد هدف API شامل کد خطا و جزئیات ساختاری است؛ حذف متن قدیمی خطای بک‌اند هنوز باقی است.

قابلیت‌های پیشنهادی بعدی:

- **استودیوی کانفیگ:** فرم و JSON کنار هم، بررسی سازگاری، پیش‌نمایش تغییر و بازیابی نسخه.
- **مسیر خرید:** دنبال‌کردن پرداخت، کیف پول، سفارش، تأیید نود و تحویل در یک نما.
- **راهنمای اتصال:** توضیح نتیجهٔ بررسی اتصال با شواهد و تشخیص تحت کنترل مشتری.
- **مهاجرت آزمایشی:** پیش‌نمایش ورود مشتری و پلن، رفع تعارض و اعتبارسنجی پیش از فعال‌سازی.
- **دستورهای اتوماسیون:** شرط و اقدام مشخص، سابقهٔ اجرا و مسیر بازیابی.
- **راهنمای آمادگی نصب:** دامنه، TLS، ثبت بات و بررسی پشتیبان تا اولین نصب تأییدشده.

این پیشنهادها پیش از اجرا به طراحی و معیار پذیرش مشخص نیاز دارند.

## آزمون و محدودیت‌ها

[راهنمای تست‌ها](docs/testing.md) مرز آزمون واحد، API، مرورگر و اجرای واقعی زیرساخت را توضیح می‌دهد.
پوشش پروتکل، اعمال پیوستهٔ محدودیت چندنودی، اتصال در شبکهٔ هدف، پرداخت بانکی واقعی و بازیابی عملیاتی
باید مستقل بررسی شوند؛ قبولی مؤلفه‌ای جای آن‌ها را نمی‌گیرد.
